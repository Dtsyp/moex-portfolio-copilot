# MOEX Portfolio Copilot

Система поддержки портфельных решений для ликвидных акций Мосбиржи. Семестровый проект по курсу ML System Design.

> **Дисклеймер.** Проект образовательный. Он не является индивидуальной инвестиционной рекомендацией, не предназначен для реальной торговли, а его результаты не гарантируют доходность.

## Идея

Система ежедневно собирает цены, макро-данные и новости в point-in-time хранилище, ранжирует бумаги на горизонтах 1 неделя и 1 месяц и строит целевой портфель с учётом риска и издержек. Главная цель проекта: воспроизводимый пайплайн, честная walk-forward оценка и мониторинг, а не максимизация доходности.

## Планируемый скоуп MVP

- Рынок: 30-50 ликвидных акций Мосбиржи (с восстановленным историческим составом индекса)
- Горизонты: 1 неделя и 1 месяц
- Сигналы: LightGBM-ранжирование + сентимент русскоязычных новостей как признак
- Портфель: HRP / risk parity с ограничениями на веса и оборот
- Бенчмарки: индекс Мосбиржи (IMOEX/MCFTR), равновесный портфель, risk parity без сигналов
- Оценка: walk-forward бэктест с комиссиями, IC, Sharpe, max drawdown, turnover, бутстрэп-интервалы

## Источники данных

| Источник | Что даёт |
|---|---|
| MOEX ISS | Дневные свечи, состав индексов, дивиденды |
| MOEX ALGOPACK | 5-минутные свечи с микроструктурными метриками (опционально) |
| ЦБ РФ | Ключевая ставка, курсы валют |
| RussianFinancialNews (Hugging Face) | Русскоязычные финансовые новости |
| RSS (Интерфакс, РБК, Финам) | Свежие новости |

Сырые данные биржи в репозиторий не добавляются: в нём лежат только скрипты загрузки. Условия использования данных MOEX ISS допускают использование «для ознакомления».

## Целевая архитектура

1. Ingestion (идемпотентные ежедневные джобы, bronze-слой с сырыми ответами)
2. Хранилище: Parquet + DuckDB, слои bronze/silver/gold, у каждой записи `event_time` и `available_at`
3. Feature store: point-in-time join по `available_at`
4. Обучение: LightGBM, MLflow для экспериментов и реестра
5. Walk-forward бэктест с эмбарго, комиссиями и проскальзыванием
6. Оптимизация портфеля: HRP, risk parity (Black-Litterman во второй итерации)
7. Объяснения: вклад признаков и связанные новости; LLM-слой отложен за пределы MVP
8. Сервинг: ежедневный batch-инференс, FastAPI, веб-интерфейс
9. Мониторинг: качество данных, дрифт признаков, деградация IC
10. MLOps: Docker Compose, CI, тесты на утечки, `make reproduce` (план для полного бэктеста)

Подробности: [docs/ml_system_design_doc.md](docs/ml_system_design_doc.md).

### Запуск

Нужен Python 3.12. Команды выполняются из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
python -m pip install -r requirements-eda.txt
make eda
make lint test
```

Без `make`: `python scripts/download_data.py`, затем
`python scripts/run_eda.py --offline`. Первый запуск требует доступа к
`iss.moex.com`, `www.cbr.ru`, `huggingface.co` и CDN, на который Hugging Face
перенаправляет загрузку Parquet. Повтор по сохраненным ответам: `make eda-offline`.
Он проверяет хеши кэша и не обращается к сети. Если кэш не был сохранен,
offline-запуск завершится ошибкой; одного содержимого GitHub недостаточно.

Конфигурация среза: [configs/eda.json](configs/eda.json). Кэш и обработанные таблицы
хранятся локально в `data/` и не коммитятся. Публичные результаты — агрегированные
проверки и графики; тексты новостей и строки биржевой истории не публикуются.
Для обновления ответов по тем же URL сначала архивируйте `data/` вместе с
`reports/eda/sources_manifest.json` вне checkout; следующий запуск создаст новый
локальный срез. Существующие ответы загрузчик повторно использует.
Прямые зависимости закреплены в `requirements-eda.in`, полное разрешение —
в `requirements-eda.txt`; фактические версии записываются в manifest.

EDA ограничен периодом 2015–2024. Holdout 2025–2026 не загружается для анализа.
Квартальные срезы IMOEX задают исследовательский список бумаг, а не готовый
point-in-time универсум. Дневные свечи и рассчитанные по ним ценовые доходности
не заменяют проверенные цены основной сессии и доходности с дивидендами.
